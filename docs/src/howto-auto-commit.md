<h2 id="when-to-use">When to use it</h2>

<p>Auto-commit-per-turn is the default for a reason: it gives
every charm a clean, attributed history without the human in the
loop having to remember to commit. Three concrete moments where
it earns its keep:</p>

<ul>
  <li><strong>Reviewing the agent's work.</strong>
<code>git log --oneline</code> reads as the session's
summary; each commit's body carries the user prompt that
triggered the edits.</li>
  <li><strong>Reverting one bad turn without losing the rest.</strong>
<code>git revert HEAD</code> targets just the most recent
agent commit; earlier good work stays put.</li>
  <li><strong>Sharing progress.</strong>
<code>git push</code> after a session ships a clean history
rather than a single sprawling "agent did stuff" commit.</li>
</ul>

<h2 id="how-it-works">How it works</h2>

<p>Two hooks fire around every conversation-loop turn when
<code>state.git_auto_commit</code> is on (the default):</p>

<ol>
  <li><strong>Pre-cantrip commit.</strong> If the working tree
is dirty when the user types, Cantrip commits the dirty
state first as
<code>chore(pre-cantrip): save in-progress work</code>.
This means your hand-edits never get squashed into the
agent's commit.  Untracked files participate too &mdash; the
pre-commit runs <code>git add -A</code>.</li>
  <li><strong>Agent commit.</strong> After the final assistant
message lands, Cantrip walks the turn's tool calls for
<code>write_file</code> / <code>edit_file</code> /
<code>multi_edit</code>, stages the touched paths
explicitly via <code>git add -- &lt;paths&gt;</code> (no
catch-alls), and commits with a Cantrip co-author trailer.
The subject line is generated by the
<a href="howto-light-models.html">light provider</a>
when one is configured; without one we fall back to
<code>agent: &lt;truncated user message&gt;</code>.</li>
</ol>

<h2 id="commit-shape">Commit message shape</h2>

<pre><code>feat(charm): add ops-tracing integration

Prompt: Add ops-tracing to src/charm.py so we can trace hook execution
in the dev model.

Touched:
  - src/charm.py
  - charmcraft.yaml

Co-Authored-By: Cantrip &lt;noreply@canonical.com&gt;</code></pre>

<p>Subject line is capped at 72 characters, prompt is capped at
~280 characters, the touched-file list truncates after 20
entries with a "<em>and N more</em>" hint.</p>

<h2 id="opt-out">Disabling auto-commit</h2>

<p>Three ways:</p>

<ul>
  <li><strong>One session:</strong>
<code>cantrip run --no-auto-commit .</code></li>
  <li><strong>Mid-session:</strong>
<code>/auto-commit off</code></li>
  <li><strong>Re-enable mid-session:</strong>
<code>/auto-commit on</code></li>
</ul>

<p>When auto-commit is off, agent edits stay in the working
tree until you commit them yourself. The pre-cantrip
dirty-commit also skips, so a turn that starts with a dirty
tree just runs the agent against that state.</p>

<h2 id="undo">Interaction with /undo</h2>

<p><a href="howto-undo.html"><code>/undo</code></a>
restores the working tree from the snapshot taken just before
the user turn. Because snapshots and the user's repo are
independent, the auto-commit's contents are still in
<code>git log</code> after <code>/undo</code> &mdash; HEAD points
at the agent commit but the working tree no longer matches it.</p>

<p>To reconcile, run one of:</p>

<ul>
  <li><code>git reset --soft HEAD~1</code> &mdash; drop just the
Cantrip commit from history; the working tree (already
restored from the snapshot) becomes the new tip.</li>
  <li><code>git revert --no-commit HEAD</code> &mdash; preserve
the commit in history but stage its inverse, ready for you
to commit as a "revert agent change" entry.</li>
</ul>

<h2 id="what-it-is-not">What auto-commit is <em>not</em></h2>

<ul>
  <li>Not a push. Cantrip never runs <code>git push</code>; the
user pushes when they're ready.</li>
  <li>Not a snapshot replacement.
<a href="howto-undo.html"><code>/undo</code> snapshots</a> still
fire — the snapshot system runs in a hidden parallel git
repo independent of your charm's repo.</li>
  <li>Not a remote-history rewriter. Auto-commit creates new
commits on the current branch; it never amends, force-pushes,
or rewrites published history.</li>
  <li>Not a GPG signer. The commits run with
<code>--no-gpg-sign</code> so an unattended session never
blocks on a passphrase prompt. Set
<code>CANTRIP_GPG_SIGN=1</code> to re-enable signing.</li>
</ul>
